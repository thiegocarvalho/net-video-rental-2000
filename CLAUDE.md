# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Net Video Rental 2000** (title in `index.html`; repo/folder name "RentalTube") — a browser-based 3D VHS rental store ("locadora") built with Three.js, styled after Windows 95 / PlayStation 1-era aesthetics. It turns a YouTube channel/playlist RSS feed into a shelf of virtual VHS tapes that the player can browse, pick up, and play on an in-scene CRT TV/VCR. Code comments and the README are mostly in Portuguese.

There is no build step, no bundler, no package.json, and no test/lint tooling. It's plain ES modules loaded directly by the browser. Three.js r128 (0.128.0) is resolved through an **import map in `index.html`** (jsdelivr CDN) — source files just `import * as THREE from 'three'`, plus `three/examples/jsm/loaders/GLTFLoader.js`, `.../renderers/CSS3DRenderer.js` and `.../utils/SkeletonUtils.js` (exports the `SkeletonUtils` object in r128). To bump Three.js, update all four import-map URLs in `index.html` together. `libs/qrcode.min.js` is vendored; the YouTube IFrame API is loaded via a `<script>` tag in `index.html`.

## Running locally

Must be served over HTTP (not `file://`) for CORS on textures/models:

```bash
npx http-server -p 8080 -c-1
```

Open `http://localhost:8080/`. Deep-link a feed with `?channel_id=UC...`, `?playlist_id=PL...`, `?id=...`, or `?c=...` (bottom of `src/main.js`; it auto-clicks `#btGo`).

## Repo clutter to ignore

If `patch_*.js` files in the root or a `scratch/` folder exist locally (untracked), they are one-off Node scripts (past string-replace edits, ad-hoc Puppeteer-style checks): not part of the app, not imported anywhere — don't extend them; edit the real files in `src/` directly. `models/*.glb` are third-party assets, each with an adjacent `*.credits.txt` (one per loaded model — the orphan credit files were removed, so a `.credits.txt` without its `.glb` is a mistake, not history); `posters/` holds exterior poster images. `FINAL_GAME_DESIGN.md` and `I18N_DESIGN.md` are the design docs (both implemented, i18n included).

## Conventions

- Single render mode: native resolution, pixel ratio capped by `MAX_PIXEL_RATIO` (1.5) in `Engine.js`, or by `TOUCH_MAX_PIXEL_RATIO` (1.25) when `TOUCH` (use `resizeRenderer`). There is deliberately **no** low-res "PS1 mode"; the PS1 look comes from art (low-poly, small nearest-filtered textures, fog, grimy palette), not from the render resolution.
- The 2D HUD is Resident Evil-inspired (minimal, contextual, dark panels, gold accent), styled in `css/styles.css`; `?debug` shows `#fps`/`#diag`.
- `?debug` (`DEBUG` in `ui/UIManager.js`) also gates every test/debug global: `window.S`, `SESSION`, `resetWorld`, `unlockAchievement`, `spawnCustomerNow`, `scene`, `customerClock`/`customerLab`/`customerDebug`/`customerGroup`, `huntDebug`, `resetStoreAfterNightmare`, `resetExplodedDoor`, `muteTv`/`toggleTvMute`, the [C] key / `#mb6` "CLIENTE" button and `?test_customer`. Always exposed because the game itself reads them through `window`: `P`, `camera` (CustomerEvent/HeroFinale), `sightFX` (Hunt/CustomerEvent), `unmuteTv` (Counter), `setPlayingTapeCase` (Tape), `ytPlayer`/`onYouTubeIframeAPIReady`. Test scripts must load with `?debug`.
- Avoid per-frame allocations and redundant DOM writes (cache last value). Texture helpers in `core/Utils.js`: `cached`, `pixelate`, `dither`, `rng`.
- Commits: Conventional Commits, no AI co-author trailers.

## Architecture

`src/main.js` (~2700 lines) is the composition root: DOM listeners, input/pointer-lock, interaction/picking, `walkIn()`, the render loop `tick()`, and YouTube player init. Scene construction lives in separate modules, which main imports.

### Two scenes, one renderer

- **`src/scenes/Exterior.js`** — storefront scene (`extScene`/`extCam`), shown before the player enters.
- **`src/scenes/Interior.js`** — builds the 5.2m × 8.2m interior (`scene`, `camera`, `M` materials, `RW/RD/RH`) by delegating to `src/scenes/interior/{RoomShell,Shelf,Furnishings,Counter}.js` and re-exporting what main needs. It also owns the shared arrays `solids`, `interactables`, `slots` passed to those builders as a `ctx`. The right wall is spaced so the player can walk between the three props: cabinet z 1.85 (`CAB.z` in `Cabinet.js`), vending machine z 3.35 and arcade cabinet z 4.95 (both in `Furnishings.js`) — move a `position` there and its `ctx.solids` entry together, or an invisible wall appears.
- `S.phase` (`'outside' | 'entering' | 'inside'`, in `src/core/State.js`) selects which scene `tick()` draws; `walkIn()` animates the transition.
- **Static meshes are merged, then frozen:** `mergeStatic()` (`scenes/interior/shared.js`, run at the end of `Interior.js`/`Exterior.js`) merges static `boxAt`/`planeAt` meshes into one geometry per material, skipping dynamic/hidden/typed/transparent ones. `shared.js` also has `nearestTex`, `stampMaterial`, `psxModel` (GLB -> Lambert + nearest filter). Do not rely on a mesh staying a separate object unless it is interactable or `userData.dynamic`. For what `mergeStatic` can't take, `shared.js` has `mergeMeshes(list, parent)` (any geometry, same material; used for troffers/halos/pools/shade bands, pine trees, lamp posts) and `mergeModel(root)` (static GLB: one mesh per material, e.g. `old_tv.glb` ~50 -> 8 draw calls; call it after `psxModel` and before measuring nodes by name).
- **Static meshes are frozen** by `freezeMeshes()` (`src/graphics/Engine.js`), called at the end of `Interior.js`/`Exterior.js`: it sets `matrixAutoUpdate = false` on every mesh without `userData.dynamic = true`. Anything whose *transform* changes after construction (tapes, doors, hand, deck tape) **must** set `userData.dynamic = true`. The flag does not affect material/texture swaps.

### The TV is a hybrid of WebGL and DOM

The real YouTube player lives in a DOM `<div id="yt-player">` placed on the TV tube through a **`CSS3DRenderer`** (`cssRenderer` from `Engine.js`, object built in `scenes/interior/Counter.js`). The CSS layer (`#css-app`) sits **behind** the WebGL canvas (the renderer has `alpha: true`); while the video is visible `main.js` swaps the TV glass to `screenHoleMat` (alpha 0, no blending) so the video shows through, and anything in front of the TV (held items, thrown cans, the customer) correctly covers it. Don't put DOM controls inside `#yt-container` expecting clicks: the canvas is above them. `src/services/YouTubePlayer.js` (`initYtPlayer`, `ytTick` at 4 Hz, mute/volume helpers) owns the player; it creates `window.ytPlayer` by polling for `YT.Player` — deliberately *not* relying on `onYouTubeIframeAPIReady`, which never fires reliably for an ES-module entrypoint (see comment in `YouTubePlayer.js`). The video is always started muted, then unmuted via `unmuteTv`. The 2D `#fx` overlay canvas (static, OSD, CRT curvature/vignette) is drawn by `graphics/ScreenFX.js` (`drawFX`, `syncCRT`, which maps the 3D screen mesh corners to 2D).

### Interaction model

- FPS pointer-lock movement (WASD + mouse) in the interior; raycast picking (`pick()`/`hovered` in `main.js`) against `interactables`. Touch devices get the scheme below instead.
- Touch (`TOUCH` = `matchMedia('(pointer:coarse)')` in `ui/UIManager.js`, which adds `body.touch`; `ui/TouchControls.js`, `initTouchControls(env)` called from `main.js` with `huntMode/canLook/onTap`; a no-op on desktop): `#stick` is an analog joystick (radial dead zone, `touchMove.f/r` in -1..1, added to WASD in the `tick()` loop, speed scaled by tilt); dragging anywhere else on the canvas looks (`LOOK_SENS`, pitch clamp ±1.2; while inspecting it rotates the held item); a short tap (<280 ms, <12 px) calls `onTap` -> `pick()` + `use()` at the finger (ignored while inspecting or holding the shotgun: firing is `#mb7`). Each finger is a `pointerId`, so stick and look work together. `touchBusy()` in `main.js` (not inside, terminal/modals/arcade/GTA/file open, cutscene) disables it; `resetTouchControls()` releases the fingers on state changes. In HUNT the module does nothing (`Hunt.js` has its own aim handlers on `#stick`/screen). `#mAct` holds the HUD buttons (`#mb1` USAR=E, `#mb2` VERIFICAR=F, `#mb3` SAIR=ESC, `#mb4` throw/drop, or fast-forward while watching, `#mb5` stand up while watching, `#mb7` ATIRAR; `#mb6` CLIENTE is hidden without `?debug`). Portrait: `fovFor(aspect)` in `main.js` widens the vertical FOV (max 100) to keep ~58° horizontal; landscape/desktop use the base 72 (the hero finale owns the FOV while it runs). Virtual keyboard: `visualViewport` feeds the CSS vars `--kb` (covered px) and `--vvh` (visible height) and `body.kb-open`, so panels rise above it. `#fs-btn` (TELA CHEIA / SAIR DA TELA CHEIA) toggles fullscreen where the API exists (not on iPhone); a one-time toast suggests landscape when entering in portrait. Texts in `TXT` (TouchControls) and `TXT.hintTouch` (UIManager).
- `solids` = flat `{x1,x2,z1,z2,h}` AABBs (`mouth:true` = caixa de reciclagem: papelao entra pela boca, ver ThrownCan) (`core/Collision.js` also has oriented boxes via `makeObb`, used by the rotated car; props like the TV/computer/fan/bell use `addPropSolid` with `y0`/`prop:true` and are ignored by the player's `collide()`): `collide()` uses the rectangle for the player; `h` (top height in metres, default 2) is used by thrown items (`entities/ThrownCan.js`) so they bounce off sides and land on top. Add an entry (with `h`) for any new static furniture.
- Arcade (`scenes/interior/Furnishings.js` + `enterArcade`/`exitArcade` in `main.js`): no modal. The KOF '97 emulator is an archive.org iframe in `#arcade-container` inside `#arcade-layer` (behind the canvas, like the TV hole technique); every frame `placeArcadeLayer()` fits that 640x640 box onto the 4 projected corners of the cabinet's `GameScreen_Plane` with a homography `matrix3d`. (Nested CSS3D was tried first: the browser's click hit-test cannot find elements inside it, so the mouse never reached the iframe.) The iframe starts loading by itself 2 s after the player is inside the store (`loadArcade()`, `arcade.loaded`; sitting down also triggers it); it is silent until the player clicks "Click to Begin" inside the machine. While playing, `body.playing-arcade` makes the canvas `pointer-events:none` and the iframe gets keyboard focus; ESC is caught through `fullscreenchange` (the page asks for fullscreen on entering) because a focused cross-origin iframe swallows key events. It only works on Fridays (`core/Calendar.js`); `?arcade=on|off` forces it. The source is `ARCADE_URL` in `core/Config.js`: the archive.org *embed* page (player only, no header/footer, no volume control, always starts muted); the iframe is 640x480 centred in the 640x640 box (`ARCADE_IFRAME_TOP/LEFT`, `ARCADE_GAME_TOP/BOTTOM`) and the black masks in `#arcade-container` only cover the leftover bars. Sound only exists while playing: leaving the machine (`exitArcade` -> `unloadArcade`) sets the iframe to `about:blank` (the match is lost) and, 2 s later, the muted embed preloads again. Until a player clicks "Click to Begin" the page only shows a static screenshot of the game; the 64 MB emulator download and the audio start after that click. The iframe's audio cannot be attenuated (no API), unlike the YouTube player and the car alarm (`carAlarmStart` uses a WebAudio panner); that is why it is unloaded on exit.
- Screens as HTML (`ui/ScreenLayer.js`): `createScreenLayer(el, geom, pxW, pxH)` + `placeScreenLayer(layer, camera)` fit a plain DOM element (in `#arcade-layer`, behind the canvas) onto the 4 projected corners of a 3D screen with a `matrix3d` homography (only recomputed when the camera/window change); the 3D screen swaps to an alpha-0 hole material while the element is shown. Used by the arcade and by the cashier computer: on desktop `openTerminal()` moves `#term-card` into `#terminal-container` (640x502, bound to `compScreen`, the green plane of `retro_computer.glb` measured in `Counter.js`), the camera glides to `compScreen.view` and ESC closes. On touch that 640x502 card is too small, so `ensureTerminalLayer()` moves it into a full-screen DOM overlay `#terminal-touch` instead (shown with `body.terminal-open`, height follows `--vvh`; same tabs/commands/handlers, footer button text `TXT.term.backTouch`, tapping the CLI panel focuses the prompt, and the focused input is kept visible when the keyboard resizes the viewport). While seated on desktop, `body.terminal-open` makes the canvas `pointer-events:none` so the mouse reaches the card. Away from the computer the screen keeps its idle texture. Tabs, in order: TERMINAL (command line), ESTOQUE (channel + inventory, no durations: the feed doesn't have them), CRÉDITOS. `renderCredits()` builds the dynamic credits on open: the owner's rights for the channel/playlist videos (always; from `S.channelMeta`) and, when the arcade is open (Fridays / `?arcade=on`), the KOF '97 / Internet Archive credits; the 3D-model credits are static HTML.
- Secret GTA (`zta` command in the terminal): same on-screen technique on the computer's monitor (`#gta-container`, `GTA_URL` in `core/Config.js`), no modal, real mouse/keyboard. Differences from the arcade: no fullscreen (ESC belongs to the game, so NO key leaves; only the `#gta-exit` mouse button does) and standing up *unloads* the iframe (`about:blank`), so the monitor returns to its idle screen and the player must redo terminal → `zta`.
- Terminal HELP (uso unico, `startHelpSequence`/`cancelHelpSequence` in `main.js`, strings em `TXT.term`): 1a vez na sessao (`SESSION.helpUsed`) digita uma frase, corta com glitch (texto embaralhado, RGB, tremor do card), reinicia o computador (tela preta, beep POST, boot RENTAL-OS) e volta ao terminal limpo; depois so mostra 'comando desabilitado'. Entradas sao ignoradas durante a sequencia e os popups de achievements ficam suspensos (`setAchievementsPaused`); `closeTerminal()` (ESC e `resetWorld`) cancela timers e retoma os popups.
- Desk fan (`fan` in `Counter.js`): starts OFF (`fan.on=false`; turning it on drops the ZTA paper, see Pig.js); interactable (E toggles `fan.on`); blades spin up/down with inertia (`fan.speed`, rad/s) and `fanHumUpdate(level, rate)` plays a layered sound (air noise pulsing at the blade rate, a two-saw motor whose pitch follows the spin so start-up/spin-down whine, low rumble) whose level follows speed x distance x door occlusion x ducking.
- Trash-bin secret (`inspectBin`/`breakBin`/`updateBinEgg` in `main.js`, `binCtl` from `Furnishings.js`): 15 empty-handed inspections (E or F on the bin) break it. The bin blinks 3x and vanishes (`core/Blink.js`), its hitbox/solid are removed and `binInfo.active=false`, `ejectBinTapes()` launches the tapes stacked inside, and a roast turkey (`models/chicken.glb`, Kenney, CC0) sits on the floor for 5 s then blinks away. `returnToTitle()` calls `restoreBin()`. Door debris now last 6 s (`DEBRIS_LIFETIME`) before the same blink-out.
- Held-item priority: `pick()` filters targets while holding something (tape: only VCR, TV, empty shelf slots; can: only vending machine and bin); E with no target puts the tape back / drinks the can.
- Throwing: `G` throws the held can (vanishes: blinks 3x on the floor via `core/Blink.js`, or disappears inside the bin) or the held tape (never vanishes: rests on the floor/furniture or stacks in the bin, `binInfo.pile`). The bin is 1.5x scaled; its mouth is measured from the model into `binInfo`.
- Tapes: S.tapes holds the tape *meshes* (`userData.data` is the tape data, `data.mesh` the mesh, `userData.home` the shelf slot). Empty shelf slots are invisible `shelf_slot` interactables; E with a held tape puts it there. `VCR.insert()` with a tape already in the deck sends the old one back to the shelf (`eject({toShelf})`).
- TV remote while seated: W/Space play-pause, A rewind, D fast-forward, E eject (stay seated), S/F stand up.
- `slots` = world-space tape positions/rotations produced by the shelf builder (`scenes/interior/Shelf.js`). The feed is truncated to `slots.length` (`cat.slice(0, slots.length)` in `main.js`), so visible tapes are capped by shelf capacity (currently 15).

## Internationalization (i18n)

Locales `pt-BR` (source), `en-GB`, `es-ES`; details in `src/i18n/README.md`, plan in `I18N_DESIGN.md`. `src/i18n/index.js` exports `t(key, params)`, `plural(key, n, params)`, `getLocale`, `setLocale`, `applyStaticTranslations`, `LOCALE_LABELS`; detection is synchronous at module load: `?lang=` (persisted) > `localStorage('rental_lang')` > `navigator.languages` > `pt-BR`. The locale is fixed for the page's lifetime (modules may call `t()` at load); switching reloads. Dictionaries are split per namespace, `src/i18n/<locale>/{ui,main,entities,scenes}.js`, merged by `src/i18n/<locale>.js` (`merge.js` throws on duplicate keys); each namespace owns its key prefix (`ui.*` = index.html/interface). `src/i18n/boot.js` runs from an inline module in `index.html` before `main.js`: `initI18nUI()` sets `<html lang>`, translates `[data-i18n]` (text), `[data-i18n-aria]`, `[data-i18n-attr="attr:key;..."]` and `[data-i18n-html]` (whitelisted b/i/em/strong/small/br/span[class], repo keys only), `og:locale`, and builds the PT/EN/ES picker in `#card` and in the ESTOQUE tab. A switch saves a snapshot in `sessionStorage('rental_resume')` (`setResumeProvider(fn)` supplies it, `#feed` is added automatically) and reloads keeping the query string; `consumeResume()` reads+clears it on the next boot. Rules: no player-visible string outside `src/i18n/`; elements main.js rewrites at runtime get no `data-i18n`; don't translate terminal commands, the game name, proper names/credits authors, `?debug` text; `node tools/check-i18n.mjs` must pass.

## Adding scene decorations

Add furniture in the relevant `src/scenes/interior/*.js` builder (usually `Furnishings.js`) using `boxAt(scene, w, h, d, material, x, y, z, [rotY])` / `planeAt(...)` or a GLB via `loadModel` + `fitModel` + `matchStyle`. Push clickable objects into `interactables`, push bounds into `solids` if they should block movement, and mark anything animated `userData.dynamic = true`.
